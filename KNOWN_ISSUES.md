# Known scope and remaining issues

This is the final manuscript-stage source snapshot, not a new corrected-performance claim.

1. **Code/checkpoint pairing.** The final root model removes an extra multiplication by Pmax in power projection. Historical beta-0 weights still store validation SE128.5288; the final forward gives87.9002 on the400-scene validation set. A controlled projection-only ablation restored128.5331 with the old rule. That restoration is diagnostic, not a valid power fix. Parameters load because layer shapes did not change; state_dict does not serialize the forward formula.
2. **Physical power convention.** Generated W retains norm squared Pmax/K, while the network also multiplies by sqrt(P). Projection on the sum of P is therefore not the same as projection on actual radiated power. The unit-norm precoder and physical-P convention must be unified, followed by matching training/evaluation. These scientific changes have not been silently made in this source snapshot.
3. **LSFC, association, aggregation.** The historical arrays lack true Beta files; main training estimates Beta from instantaneous H. The final generator now exports true Beta, which newer helpers can read, but the legacy main loader still uses its original fallback. Normalized Beta can produce negative linear aggregation weights. The transmit power is not strictly zeroed outside the service mask.
4. **Overhead definitions.** KL/ln2 is a variational information-rate proxy, not measured serialized network traffic. Three-round FP32 uplink latent payload is10% of full FP32 CSI under the supplied dimension ledger. The KL exporter averages refinement rounds before multiplying by AP count. Downlink, auxiliary information and wire headers require separate accounting. Table I's full beta-to-equivalent-budget mapping is not supplied by the overhead exporter. Several SE ratios in that script are historical entries, now explicitly labeled, not fresh baseline runs.
5. **Training locality.** train_federated_cluster.py uses joint-data gradients in one process. It is not a multi-device data-local deployment. The newer ibfl model used for comparison scripts has a different architecture/schema, and its optional proposed checkpoint is absent from the supplied final folder.
6. **Comparison cohorts.** Historical Table III percentages can be reconstructed but their original subsets and historical reference denominator differ. A physically consistent paired comparison is still needed for a new performance claim. The original LSFC83.78% entry has not been tied to a matching run; default fractional fallback replay gave83.31% on the checked300-scene subset.
7. **Privacy protocol.** The provided attack is a supervised z-to-Beta decoder, not a gradient-matching inversion attack. Attack normalization uses the full attack pool, and held-out attack loss is used for learning-rate scheduling. Describe this protocol and use a separate confirmation set for stronger privacy claims.
8. **Historical-normalized plots.** corrected robustness and precoder-swap scripts expose anchored results. These historical clean-score normalizations must not be presented as direct forward SE. Both raw and anchored values remain available.

Published SE and physical feasibility need to be reassessed after resolving the model conventions. Syntax, execution, saved-number replay and physical validity are separate checks.
